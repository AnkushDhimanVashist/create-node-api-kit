What every project gets

The parts every serious API needs, done once, the same way everywhere.

Layered structure

Routes, services and repositories in one folder per feature. Swap the database without touching business logic.

Zod validation

One schema gives you runtime validation, TypeScript types and the OpenAPI docs.

Safe configuration

Environment variables are validated at startup. A missing or invalid one stops the server with a clear message.

One error format

Throw notFound() anywhere. Every error leaves as the same JSON, and internals never leak.

Security defaults

Secure headers, CORS, body size limits and per-IP rate limiting, on from the first run.

Ops-ready

Pino logging, liveness and readiness health checks, graceful shutdown on SIGTERM.

Tests that run anywhere

Vitest API tests against an in-memory repository: no database needed locally or in CI.

Tooling + CI

ESLint, Prettier, EditorConfig and a GitHub Actions workflow that lints, type-checks, tests and builds.

Project structure

Every request flows through the same three layers.

route / controller→service→repository→database 
src/
├── server.ts              # entry: connect, listen, graceful shutdown
├── app.ts                 # builds the app (shared by server and tests)
├── config/env.ts          # environment variables, validated with Zod
├── lib/                   # logger, db, redis, cache, jwt, password, shutdown
├── common/                # errors, validation, middleware
├── docs/                  # OpenAPI document + Swagger UI
└── modules/
    ├── health/
    ├── auth/
    └── users/
        ├── user.routes.ts      # HTTP: parse input, send response
        ├── user.service.ts     # business rules
        ├── user.repository.ts  # the only file that talks to the database
        ├── user.schema.ts      # Zod schemas
        └── user.entity.ts      # types + the public user shape
tests/

NestJS projects follow Nest conventions (modules, controllers, guards, pipes, filters) on top of the same shared core.

Adding a feature

Say you need products:

  1. Copy src/modules/users to src/modules/products and rename the files.
  2. Describe the request bodies in product.schema.ts with Zod.
  3. Write the queries in product.repository.ts and the rules in product.service.ts.
  4. Register the routes in src/app.ts (or the module in app.module.ts for NestJS).
  5. Add a test in tests/.
